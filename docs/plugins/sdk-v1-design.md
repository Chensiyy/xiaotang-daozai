# 岛仔插件 SDK v1 评审稿

## 1. 插件如何工作

SDK 是岛仔提供给插件作者的一组公开约定。宿主指运行插件的岛仔。你提供一份清单和几段函数，岛仔负责调用、画界面和保存结果。

第一版采用**每次调用都从头运行**的写法。函数只根据输入计算并返回结果，需要记住的内容放进返回值的 `storage`。两次调用之间，脚本变量会消失。宿主负责读写磁盘、安排刷新和接收用户点击。当前本地试用版可运行无外部权限的 QuickJS 待办卡片。QuickJS 是执行 JavaScript 的引擎。[运行环境实测](runtime-spike.md) · [本地安装](local-install.md)

## 2. 我能写哪些功能

先试[发薪倒计时](../../spike/examples/payday/plugin.json)和它的[完整入口脚本](../../spike/examples/payday/main.js)。复制整个目录，修改清单中的 ID（识别插件的固定名称）和显示名称，就能安装第二份。`plugin.json` 是插件的清单。JSON 用字段名和值来记录设置、刷新间隔和权限。

当前宿主按全局函数名调用 `refresh(input)`。输入是 `{settings, today, storage}`，日期格式为 YYYY-MM-DD，首次调用的存储值为 `null`。当前返回值为 `{card, storage}`，其中 card 为文字，storage 为本次完整的私有数据。下面这段可以直接替换样例的 main.js。

```js
function refresh({ settings, today }) {
    const days = Math.round((Date.parse(settings.target) - Date.parse(today)) / 86400000);
    return { card: settings.title + " · " + days + " 天", storage: { lastDays: days } };
}
```

| 能力与进度 | 作者怎么写 | 用户在哪里用 |
| --- | --- | --- |
| 文本、日期设置 · 已实现 | 清单的 settings 列出字段，在上例读取 settings.title 和 settings.target | 待办与置物的插件设置 |
| 材质数字参数 · 已实现 | 清单声明 `type: "number"`、`min`、`max`、`step` 和字符串形式的 `default`。着色器按清单顺序用 `param(index)` 取值，最多 32 项 | 「设置 → 外观 → 材质」，拖动滑块实时应用 |
| 脚本插件的开关、分段、数字 · 待宿主实现 | 清单字段示意 `{key:"minutes",type:"number",min:5,max:180,default:45,label:"提醒间隔"}`。开关用 switch，选项用 segment 和 choices。函数读取 settings.minutes | 唯一归属设置页 |
| 文字卡、私有存储 · 已实现 | 上例返回 card 和 storage。首次的 storage 为 null，之后可用 `storage?.lastDays` 读回天数 | 展开待办页，重启后接着用 |
| 周期刷新 · 已实现 | 两个样例在清单声明 `"refreshSeconds":60` 和 timer 能力。到期由岛仔调用 refresh | 卡片按期更新 |
| 常驻、固定、临时卡 · 待宿主实现 | `function refresh(i){return {cards:[{id:"job",mode:"temporary",text:i.settings.title,ttlMs:5000}]}}` | 常驻栏、临时位置，用户自行选择固定 |
| 独立模块、列表、详情、表单 · 待宿主实现 | 清单声明 module 与按钮 `actions:["save"]`。示意 `function action(i){return {page:{kind:"detail",text:i.form.text},storage:{note:i.form.text}}}` | 岛上功能栏查看、编辑，侧栏调偏好，页面管理启停 |
| 日程来源 · 待宿主实现 | `function refresh(i){return {calendar:[{id:"anniversary",title:i.settings.title,date:i.settings.target}]}}` | 日程里的来源，按来源和条目 ID 更新 |
| 歌词来源 · 待宿主实现 | `function refresh(i){return {lyrics:{trackId:i.track.id,lines:i.source.lines}}}`。换歌后宿主只接收当前曲目的结果 | 原音乐页 |
| AI 额度来源 · 待宿主实现 | `function refresh(i){return {quota:{windows:[{label:"本周",period_secs:604800,remaining_pct:i.source.remaining}]}}}` | 原额度面板 |
| 专注事件和提醒 · 待宿主实现 | 在清单的 permissions 中声明 `{"events":["focus.finished"],"notifications":true}`，能力列出 event、notification 和 storage。示意 `function event(i){return {notice:"专注已完成",storage:{count:(i.storage?.count ?? 0)+1}}}` | 专注设置选择是否自动记录，岛上显示提醒 |
| 受控网络、只读文件 · 待宿主实现 | 清单声明数据来源和权限。宿主先取数，再作为 source 交给函数。示意 `function refresh(i){return {card:i.source.status}}` | 用户确认域名或选择文件后查看结果 |
| 皮肤、表情、图标 · 待宿主实现 | 无代码包清单片段 `{"runtime":"assets","capabilities":["appearance.skin"],"assets":["theme.json"]}`。表情与图标分别声明 appearance.pet、appearance.icon | 原外观选择器，可切回内置素材 |
| GPU 材质 · 已实现 | 清单用 `runtime: "material"`、`owner: "appearance"`、`appearance.material` 能力和 `screen.backdrop` 权限。WGSL 入口实现 `material()`，沿用[材质接口](gpu-material.md) | 「设置 → 外观 → 材质」，同一时间选用一个材质，需开启 Direct3D 12 兼容渲染 |

拟议的 action 接收按钮 ID、表单值，event 接收事件名及内容，二者和 refresh 都返回一次调用的展示结果和要保存的数据。表中标为待实现的字段用于讨论。宿主需要支持对应的清单字段和输入输出后，作者才可以试装这些示例。

## 3. 用户去哪里用，去哪里调

用户习惯去原功能完成的事，可以往原设置页加一项。皮肤进入外观选择器，歌词来源进入音乐设置。只需要看一眼的内容可以做卡片，少量参数仍放在所属页。

用户要反复编辑便签、管理纪念日，或专门查看打印进度、温度和告警时，可以新增独立模块。作者决定展示哪些内容及其顺序，岛仔负责配色、字体、缩放和点击。正文和一次性输入在功能页编辑，默认排序等偏好在模块设置页修改。

初版若实现独立模块，清单用 `owner: "self"` 并声明 module。岛仔按照固定 ID 找到模块入口、设置入口和页面管理开关。作者无需填写页面编号。岛上的设置按钮和「前往设置」打开同一处。

每个插件只有一个主要设置归属。「我的插件」统一提供启停、卸载和前往设置。页面管理控制模块运行。设置页复用岛仔已有的开关、选择、数字、文本行和功能标题卡，保留必要设置与关键提醒，合并重复提示，内容多时才收起低频选项。

## 4. 关闭后会发生什么

岛仔分别记住所属模块开关、用户对插件的启用选择，以及各个显示位置的开关。模块和插件都允许时才调用插件函数，显示位置开关只影响对应位置。独立模块与其插件共用同一个启用选择。

| 用户操作 | 应看到的结果 |
| --- | --- |
| 只关“在日历显示农历” | 日历标注消失，小岛农历卡继续显示 |
| 关日程，再开日程 | 关闭时农历插件所有输出一同撤下。再开只恢复此前由用户启用的扩展 |
| 纪念日同时在日历和常驻栏展示 | 关日程只撤日历记录。关纪念日则撤下功能入口、固定倒数及日历记录，“我的插件”同步停用。再开找回原文、日期和固定选择 |
| 奶油皮肤换成插件皮肤，期间把胶囊改成刘海，再停用插件 | 回到奶油＋刘海。插件只在启用期间覆盖它提供的外观，基础皮肤、形状和停靠由用户掌管，材质专属选项只在支持它的皮肤上生效 |
| 停用后重启，或卸载 | 停用立即撤下输出，宿主停止发起新调用。已经开始的一次计算即使稍后返回也丢弃结果。重启保持停用，卸载可选择保留或删除数据 |

修改设置、关上级模块或重新安装时，同样作废此前发出的计算。插件重新启用后按当前设置重新计算。单选来源由岛仔记住，当前来源不可用时回到最近一次可用的选择。未获授权、执行出错或超时的调用，其结果一律作废。

## 5. 谁可以读什么

权限说明用户允许岛仔替这个插件做哪些事。安装前看作者、归属和权限摘要，首次启用确认具体用途，更新时新增的权限单独确认。撤权后岛仔停止取数并丢弃旧请求的结果。

本地 JS 卡片插件只接受空权限。材质插件首次启用时单独确认 `screen.backdrop` 权限，岛背后的像素只在本机用于材质绘制，着色器可采样底片纹理，像素不保存、不上传。

正式版拟允许清单列出 HTTPS 网站的完整域名、订阅事件、用户选择的只读文件。岛仔按插件身份检查每个请求，只连接允许的域名和端口，跳转时重新检查，拒绝本机和内网地址，限制大小与等待时间。文件由系统选择器返回，岛仔检查实际文件位置和读取资格，插件只取得批准的数据。凭据由岛仔保存在 Windows 凭据管理器，日志去掉路径、密钥和用户正文。正式版还要核对域名实际连接到的地址，以及用户选定的文件最终指向的位置，防止改用另一个地址或文件。授权只对用户选中的插件有效。拓竹所需的本机软件读取权限另见第 13 节。

## 6. 数据能留多久

用户可以停用插件一段时间再回来。宿主根据插件 ID 分开保存设置和私有数据，每次成功调用只替换本插件的数据。保留数据卸载后，用原清单位置重装本地开发包可以找回原值。

本地版把安装快照放在配置目录的 local-plugins。正式版拟把只读程序放在 `%APPDATA%\Daozai\plugins\<ID>\<版本>`，用户内容放在同级 plugin-data 的对应 ID 目录。升级时在副本上按 dataVersion 转换旧数据，成功才切换，失败继续用旧包和旧数据。在模块设置页导出的文件包含用户内容和数据版本，密钥和文件授权留在本机。卸载撤销授权、删除凭据，选择保留的用户内容由通过身份核对的同一插件认领。

## 7. 插件多久刷新一次

作者在清单填写间隔，宿主负责安排工作。当前定时卡支持 60 至 86400 秒，旧样例缺省为 60 秒。首次启用或修改设置会重新计算。界面读取最近结果，每个插件同时最多一次调用，全局最多两个后台计算。停用时画面立即撤下，稍后返回的结果作废。

QuickJS 每次计算限时 30 毫秒，脚本可分配的内存上限为 4 MiB。本地卡片单次返回最多 16 KiB。正式版拟限制普通周期至少 60 秒，实时前台内容按需开放 1 秒。每插件拟允许一个网络请求，最长 10 秒，响应最多 256 KiB。拟保留 3 个固定插件卡位置和 1 个临时位置，满时让用户选择替换。私有数据拟限 5 MiB，写满后提示清理或导出。

连续三次脚本执行失败后暂停并提示重试，是待实现的正式版规则。监控程序没启动时应提示打开依赖，设备离线时显示上次更新时间并降低查询频率。两种情况均属于数据来源状态，由宿主另行处理。

## 8. 作者交付哪些文件

从[示例清单](../../spike/examples/payday/plugin.json)开始，复制同目录的 main.js。清单中的 entry 指向包内脚本。ID 使用小写作者名与插件名，以点分隔，最长 64 个字符。

version 是插件版本，api 是需要的接口主版本，dataVersion 是存储格式版本。owner 决定设置归属，capabilities 列出使用的能力，permissions 列出授权事项。字段类型和可选值见[清单格式检查表](sdk-v1.schema.json)。该表也描述设计中的能力，本地试用目前接受的组合见[本地安装说明](local-install.md)。

宿主安装时检查字段、ID、默认值、版本、入口位置与大小，并拒绝越出包目录的脚本。重启时重新检查安装快照，出现无效记录提示重新安装。分发压缩包时还需在临时目录检查路径、链接、文件数与大小，再安装。无代码资源包只装允许的本地素材，缺少表情帧时回到内置表情。声明独立模块要同时填写 self 和 module。发布前还需检查授权与能力是否匹配、数字和选项默认值是否有效，确认包中没有可执行的外部程序。

材质包包含 `plugin.json`、一个大小不超过 64 KiB 的 `.wgsl` 入口，以及可选的文本说明文件。默认值必须是范围内的有限数字，步长为正且不大于范围宽度。控件弹簧刚度范围为 0.2 至 3，阻尼范围为 0.1 至 1。

## 9. 岛仔升级后还能用吗

建议先稳定插件身份、基本设置、卡片、存储的含义。新增可选字段要给旧包保留默认值。更改单位或删除已承诺的字段，就提升接口主版本，让新旧规则分别处理对应的包。

独立模块、来源、实时歌词和事件先标实验。遇到不兼容的实验能力时，岛仔应列出受影响的部分。更新申请更多权限时先保留可用旧版，用户同意后切换。六个月的新旧主版本并行期建议只适用于已定稿的稳定接口，期限待确认。发版前用旧版官方插件的原包，在新宿主实测安装、数据恢复、旧设置、主题和启停。遇到不支持的版本时保留数据并提示升级。

## 10. 作者如何试装和检查

当前开发者模式支持选择本地清单安装。两个样例可分别启用，在所属设置页改日期，重启检查，再卸载并选择保留或删除数据。作者改脚本后可从原位置重新安装。[可执行的试用步骤](local-install.md)

开发包与集市成品分别识别。作者可选择保存后自动重载，重新加载前收回旧输出。开发者预览拟提供深浅色、缩放、侧边停靠、模拟日期和离线状态。`daozai --plugin-test` 拟检查清单与权限、断网、启停与卸载、接口版本及不同外观。输出通过与失败项、错误位置、耗时和截图，失败返回非零结果。

## 11. 怎样把原有代码拆出来

先保留业务算法和测试，再把输入、展示结果和存储写成函数。喝水提醒原有设置限制为 5 至 180 分钟。宿主支持数字控件后，可在清单声明范围，函数读取用户输入并返回展示内容。下面的函数签名和返回值与当前卡片一致，数字控件待宿主实现。

```js
function refresh({settings}) {
    const minutes = Math.min(180, Math.max(5, settings.minutes));
    return {card: "提醒间隔 " + minutes + " 分钟", storage: {minutes}};
}
```

旧额度草案已标记废弃。迁移时从旧命令中提取请求说明和余额计算，把账户授权交给宿主，把计算改成 refresh，根据输入的服务响应返回额度数据。额度来源和真实联网待实现。旧凭据应由用户重新授权，通用的本体缺陷仍可独立修复。[旧草案说明](README.md)

可直接交给 AI 的提示词：

> 阅读我的 PR、使用场景和岛仔 SDK。列出可复用的业务逻辑和已有测试。选择一个设置归属，把定时、按钮和事件写进清单。用 refresh、action 或 event 接收输入并返回结果。生成最小包和模拟数据，标清哪些能在当前宿主试装、哪些需要新接口。验证启停、重启和卸载恢复。保留原作者与素材许可。

## 12. 投稿怎样进入集市

作者向独立插件仓库提 PR（请求维护者审核并收录改动），提交源码、插件 ID、维护者和反馈地址、许可证、权限变化、版本、构建命令、不可覆盖的版本包及测试报告。自动检查使用这些材料，小唐审核通过后才上架。

市场索引记录下载地址、字节数、SHA-256 校验值（用于检查文件内容）和发布者签名（用于核对身份）。客户端检查签名和校验值后安装。吊销清单列出停止加载的具体版本、原因、替代版本。命中吊销记录的已装版本停用并保留数据。镜像先同步包和吊销信息，再发布索引。用户通过市场上的反馈入口联系维护者。

## 13. 需要小唐决定的事

这三项决定的是正式对外承诺，当前开发包按本文的全新调用方式运行。

| 决定 | 可选方式与建议 |
| --- | --- |
| 函数如何运行 | 每次全新运行，或为每个插件长期保留环境。建议前者，恢复只依赖输入和已保存数据，首版文档与样例统一采用 |
| 怎样读取用户指定的本机软件状态 | 可先让监控导出文件，由用户选择，也可以试验单独授权给指定软件的只读服务。建议用拓竹验证第二种，安装前说明依赖，处理端口变化和撤权 |
| 旧额度命令如何退出 | 直接废弃，或为已有用户限期提供迁移期。建议停止接受新命令包，已有作者迁往受控来源接口。兼容期长度由小唐决定 |

生产阶段还需确认稳定接口的支持期限、并发与空间上限、独立进程、卸载默认选择、换维护者时的数据认领及市场签名密钥管理。

### 后续工作

以下内容还需要实际开发和试装。

作者可组合布局的独立页面是下一阶段最大的实现项，用只读打印页和可编辑便签验证。同步试验临时卡到期撤回、日程跨来源去重、切歌时清旧歌词，以及重复通知只提醒一次。开发者模式补保存后自动重新加载和自检命令。用真实换肤包、纪念日验证切换恢复与跨模块输出。评估独立低权限进程对故障隔离和启动的影响。拓竹真实取数要等本机只读权限方式确定。

### 名词解释

读清单或查看错误提示时，可以在这里对照字段的含义。

- **宿主**指安装和运行插件的岛仔。**SDK** 是作者接入岛仔所用的约定、样例和工具。
- **纯函数**指只用输入算出结果的函数。两次调用之间要保存的内容放在 `storage`。
- **QuickJS** 是宿主内运行 JavaScript 的程序。**KiB / MiB** 是容量单位，1 KiB 等于 1024 字节，1 MiB 等于 1024 KiB。
- **清单**是作者提交的 plugin.json。**ID** 是插件的固定名称。
- **接口**是宿主和插件约定的输入输出。**主版本**用来区分不兼容的规则。
- **JSON** 是由文字、数值、列表等组成的数据格式。**Schema** 是机器可读的字段检查表。
- **PR** 是向仓库提交代码或插件的审核请求。**SHA-256** 用来检查文件内容是否改变。**签名**用来确认发布者身份。
